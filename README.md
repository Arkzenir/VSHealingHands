# VSHealingHands

Makes healing another player (with a poultice, bandage or any other item using the
vanilla `CollectibleBehaviorHealingItem`) apply at different speed/amount than the
item's own values, based on the healer's character traits. Self-healing is untouched.

## How it works

No vanilla method is patched and no item's own configured values are ever mutated.
Instead, two native extension points do the work - see `OLD_VS_NEW_COMPARISON.md` for
why this replaced an earlier Harmony-based version:

- `source/HealingInterceptBehavior.cs` is a `CollectibleBehavior` that
  `VSHealingHandsModSystem` prepends (index 0) onto every item/block whose
  `CollectibleBehaviorHealingItem.Health > 0`, in `AssetsFinalize`. It detects a
  player-to-player heal (ctrl+right-click on another player, per the vanilla targeting
  rule) and, only for that interaction:
  - **Speed of application** - set through the vanilla `healingeffectivness` stat on
    the healer (the same stat armor uses), removed a tick later once vanilla's own
    completion check has run.
  - **HP amount** and **speed of healing** - handed off as a `HealingValues` to the
    *target's own* `HealReceiveBehavior`, not applied here.
- `source/HealReceiveBehavior.cs` is an `EntityBehavior` every player carries. It
  consumes that handed-off value in `OnEntityReceiveDamage`, scaling the heal amount
  and damage-over-time duration right as vanilla applies them.

Because HP/heal-speed state lives on the *target's own entity* rather than on the
shared per-item-type behavior instance, two heals in flight at once - even on a large,
busy server - never share a mutable field, so correctness doesn't depend on how the
server happens to schedule interaction callbacks.

Values come from `source/HealingHandsConfig.cs`: a set of defaults, plus per-trait
multipliers (checked via the vanilla `CharacterSystem.HasTrait`). If the healer has
none of the configured traits, the defaults apply. If they have one or more, all
present traits' multipliers compound additively (each trait's delta from 1.0 is
summed on top of 1.0) and the defaults are not used.

The config is written to (and re-read from) the world's `ModConfig/vshealinghandsconfig.json`
on first server start - edit it there.

## Building

Requires the .NET SDK and a Vintage Story install.

1. Copy `Properties/localSettings.props.template` to `Properties/localSettings.props`
   and set your game install path.
2. Build:

```
dotnet build VSHealingHands_1.22.5.csproj                # debug
dotnet build VSHealingHands_1.22.5.csproj -c Release     # release + zip
```

Debug output lands in `bin/Debug/1.22.5/Mods/vshealinghands/`. Add the `Mods/` folder
above it to the game's ModPaths for live asset reloading.

Release output lands in `Releases/vshealinghands_<version>_vs1.22.5.zip`, ready for
the mod portal.

## Layout

| Path | Contents |
|---|---|
| `source/` | C# source |
| `resources/assets/vshealinghands/` | Block, item, entity, recipe and lang JSON, textures, shapes, sounds |
| `Directory.Build.props` | Mod identity - name, id, version, description, side, authors |
| `Common.Build.targets` | Shared build logic |
| `deps/` | Vendored dependency DLLs, per game version |
| `external/` | Ad-hoc DLLs, auto-referenced |

`modinfo.json` is generated by the build from `Directory.Build.props`. Do not
create one by hand.
